# 房间生成 skill

只生成一张完整、可直接作为游戏背景候选的像素房间。

## 视觉母版

固定使用 `assets/room-visual-master.png` 作为图二。它只负责：

- 明显低分辨率、粗颗粒、硬边平涂的像素画法。
- 正交 2.5D 房间视角：后墙正面与地面同时可见，平行线不收束。

图二绝不提供家具、背景、物件数量或摆放。

## 参考图与构图

有用户参考图时，输入顺序固定为：

1. 图一：只借鉴家具类别、轮廓语言、材质感觉和配色方向。
2. 图二：只提供画法与视角。

不得复刻图一的原始房间布局、视角、透视、光影、文字或品牌；应生成一间原创房间。没有图一时，只传图二，并根据用户文字补充房间内容。

## 生成方式

- 每次用户请求只生成一张候选图；生成后停止，不自动重试、批量生成或重复展示。
- 只有用户明确要求“重试”、更换图一或更换图二后，才可再生成一张。
- 调用前在临时目录制作本轮传输副本：图一最长边 512px、JPEG 质量 70；图二最长边 512px、PNG。调用后移入废纸篓。
- 使用 `referenced_image_paths`，且只传本轮临时副本；图一在前、图二在后。没有图一时只传图二。
- 禁止使用 `num_last_images_to_include`，禁止把聊天历史图片、旧候选图、Base64 或工具完整返回值作为输入或文本回传。

## 固定 Prompt

```text
输入图片：图一只负责家具类别、轮廓语言、材质感觉和配色方向；不参考图一的家具摆放、房间布局、视角、透视、光影、文字或品牌。图二只负责低分辨率大颗粒像素风格，以及正交 2.5D 房间俯视视角与透视；严禁借用图二中的家具、背景及其摆放。

生成一间原创、完整的游戏用像素房间背景。必须清晰呈现后墙正面与地面；家具只画顶面和正面或背面，正面边线只允许水平或垂直，不画左右侧面、斜侧面、消失点或近大远小。

风格必须是真正低分辨率的大像素：以少量清楚的大色块塑造物体，轮廓硬边，阴影最多两级硬边色块；画面明亮、轻快、温暖且低噪声，家具、地面与墙面在同一颗粒尺度下保持一眼可读。禁止模糊、柔焦、半透明混色、抗锯齿、高密度细碎像素、细腻纹理、渐变、高清像素插画、写实摄影光影或写实 3D。

房间内容要充实但整洁：在主要活动区布置 6–9 件清晰可辨的大型家具或陈设，组织为 2–3 组功能区；单件主家具的正面宽度约占房间内宽的 18%–32%，不得画成小摆件。地面可见留白控制在约 25%–35%，并形成完整通道或地毯区域；家具间保持清晰间距，不重叠、不堆满边缘。先用 2–3 件主家具建立尺度，再用少量配套物补足功能区；禁止用密集小杂物、碎纹理或装饰性像素填满画面。

不同功能区必须以直线内墙或短墙段分隔；每个区域朝向客厅或中央通道必须保留宽敞的开放通口。通口不画门扇、门框或门洞装饰，却必须清楚表现空间彼此连通；禁止连续墙体封死区域、形成尽头死路或让房间彼此隔绝。

布局必须像一个紧凑、可生活的住宅：入口连接一条清晰的中央通道，客厅是公共枢纽；通道或客厅能通过开放通口到达每个功能区。客厅与餐区相邻且位于入口一侧；睡眠区靠更安静的外侧墙；厨房、储物柜和卫浴沿墙集中。家具只能摆在所属功能区，不堵通道、不漂浮在空间中央、不被隔墙切开；整体动线必须一眼可读，禁止迷宫式分区或彼此孤立的房间。

不要出现人物、宠物、品牌、文字或水印。
```

## 候选图检查

生成后只检查并展示一次。检查以下事项：

- 图一与图二职责没有混淆，且构图不是参考图的复刻。
- 视角为正交 2.5D，墙面、地面和家具关系清楚。
- 像素颗粒足够大，画面没有渐变、柔化或细碎纹理。
- 房间由 2–3 个功能区和足够大的主家具构成；空地没有超过约三分之一且形成连续通道。
- 功能区之间有清楚的内墙分隔；没有门扇、门框或门洞装饰，且每个区域都通过宽开放通口连向客厅或中央通道。
- 入口、客厅、中央通道与各功能区连通；没有被墙封死的区域、尽头死路或被隔墙切开的家具。
- 房间配色、家具和空间都易读，适合作为游戏背景。

不通过时，先指出 Prompt 的职责或风格约束问题；等待用户明确说“重试”后，才有针对性地调整 Prompt 并生成下一张。默认只在当前对话展示，不保存到项目或上传 Figma。
