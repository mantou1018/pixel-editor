# 房间生成skill

## 核心原则

- 所有输出都是游戏背景、游戏家具或游戏贴图，不是室内设计效果图。
- 用户参考图决定家具和家具风格。
- 唯一母版决定“怎么画”。
- Skill 决定“按什么流程画”。
- 模型只负责生成内容，不负责决定规则。

## 唯一母版

固定使用：

`public/assets/references/room/furniture-scene-view-pixel-master.png`

母版只负责：

- 像素分辨率。
- 视角。
- 透视。

母版中的任何家具、布局、材质、配色、软装、装饰和文字都不能使用。

## 固定流程

### 1. 输入参考图

有用户参考图时，生图输入顺序固定为：

1. 用户参考图：家具和家具风格；不参考家具摆放。
2. 唯一母版：上面的画面规则。

没有用户参考图时，只传唯一母版，内容由用户文字补充。

### 2. 生成房间

只用 `imagegen` 生成完整游戏房间背景，不提取家具。

固定 Prompt：

```text
参考图只负责家具和家具风格；不参考参考图的家具摆放。
母版只负责像素分辨率、正交 2.5D 房间视角和透视：顶面与后墙正面同时可见；平行线不收束，无近大远小、消失点或斜侧面。必须直接遵循母版。
用参考图的家具和家具风格生成完整的游戏用像素房间背景。
绝不使用母版中的任何家具、布局、材质、配色、软装、装饰和文字。
不要出现人物、宠物、品牌、文字、水印、写实摄影光影、渐变、抗锯齿或写实 3D。
```

不要自行增加母版的其他职责。

### 3. 验收和用户确认

先检查房间是否符合用户参考图和唯一母版。

不通过：先分析 Prompt 是否混淆了参考图与母版的职责；确认有问题时，修改固定 Prompt 后再生成，不提取家具。

通过后展示房间，等待用户确认。用户没有说“确认无误”前，不进入下一步。

### 4. 提取家具

只从用户确认后的房间图提取家具游戏素材。

- 保留原家具的外形、材质、配色和像素风格。
- 唯一母版继续只负责像素分辨率、视角和透视。
- 不重新设计家具，不自行增加数量、格式或背景要求。
- 提取结果仍需检查，失败只返工素材，不回改已确认的房间。

## 永久规则

- Prompt 先诊断：同类错误重复时，先修正 Prompt 的职责边界，不原样重抽。
- 母版唯一：母版只提供像素分辨率、视角和透视。
- Skill 高于 Prompt：有冲突时遵守 Skill，不听临时发挥。
- 默认只在当前对话展示，不保存到项目，不上传 Figma。
